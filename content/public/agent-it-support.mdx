## Le problème

Les demandes IT de premier niveau (mot de passe, VPN, imprimante…) arrivent en vrac et mobilisent le support pour des questions déjà résolues par le passé. Les collaborateurs veulent une réponse immédiate là où ils travaillent : dans Microsoft Teams.

## La solution

Un agent conversationnel IT dans Teams, qui suit une logique d'escalade :
1. Il cherche une solution dans la base de connaissances (historique de tickets vectorisé).
2. Si la confiance est faible ou si l'utilisateur dit « non », il cherche sur le web et synthétise une réponse sourcée.
3. Si rien ne résout le problème, il crée un ticket Jira contextualisé et propose trois créneaux d'intervention issus du calendrier Outlook.

L'utilisateur peut aussi suivre un ticket existant ou y ajouter un commentaire sans quitter Teams.

## Architecture

```mermaid
flowchart LR
  T[Teams<br/>@mention] -->|Outgoing webhook HMAC| A[FastAPI]
  A --> F[ConversationFlow<br/>machine à états]
  F --> R[RAG ChromaDB<br/>historique tickets]
  F --> W[Tavily + gpt-4o<br/>synthèse web]
  F --> J[Jira<br/>création / suivi ticket]
  F --> O[Microsoft Graph<br/>calendrier Outlook]
  F -->|Incoming webhook| T
```

- Teams impose une réponse en moins de 5 s : le serveur renvoie un accusé immédiat et traite le message en tâche `asyncio` de fond.
- Faute de droits admin pour publier un bot, l'intégration passe par des webhooks entrant/sortant ; le code Bot Framework est prêt mais dormant.
- Outlook via Microsoft Graph en flux *client credentials*, limité à un calendrier de démo (consentement admin requis pour aller plus loin).

## Fonctionnalités clés

- Réponse RAG avec score de confiance et question de validation « Est-ce que cela résout votre problème ? ».
- Fallback web automatique, sources citées.
- Création de ticket Jira avec historique de conversation et priorité estimée.
- Proposition de 3 créneaux de 30 min sur les 3 prochains jours ouvrés, sans chevauchement, et création de l'événement.
- Suivi d'un ticket (statut, assigné, dernière mise à jour) et ajout de commentaire.
- Gestion d'erreurs par service (RAG, web, Jira, Graph indisponibles, timeout > 10 s).
